# Waypoint Sequencing Follow-ups #406, #407, #408 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The unit shows the new leg in the calculation of a turn start or a sequencing (#407). It keeps the waypoint
alert after an abeam turn until the aircraft passes the old waypoint's abeam line on the new leg (#406). It computes the
turn again when the leg after the active waypoint is edited (#408).

**Architecture:** All three changes are in `NavCalculator` and `ActiveWaypoint`.

- **#407:** `NavCalculator.tick` resolves the active leg and computes its values in a method it calls once before the
  turn and sequencing decisions, and again when they changed the active leg or the top of the turn stack. The #434
  deferral (`legChangePending`/`legChangeFrom`) is replaced by a per-tick flag.
- **#406:** at a sequencing, `ActiveWaypoint` turns an abeam turn on the stack into a run-out entry that ends at the
  abeam line.
- **#408:** `ActiveWaypoint` remembers the instance of the following leg. When that instance changes, it drops the
  waypoint's own started turn and clears a lead plan.

**Tech Stack:** TypeScript (target es2017), MSFS Avionics Framework (`@microsoft/msfs-sdk`), Vitest (unit, render, flight).

**Spec:** `docs/superpowers/specs/2026-10-27-sequencing-406-407-408-design.md` (read it first; this plan argues from it).

## Review Focus

1. **A sequencing onto a duplicated waypoint, a leg of no length (#120, #27):** in the same calculation the unit goes
   on past it to the leg after it. It marks one leg change, whose DTK is that leg's, and writes no NaN to any output.
   Pinned in Task 2 by extending the existing `it.each` test "marks the leg change past a duplicated waypoint once".
2. **The next waypoint is close, and its own turn starts while the run-out of the previous waypoint is still on the
   stack:** the new turn replaces the run-out, the alert stays on without a gap, and nothing of the run-out is left
   under the new turn. Pinned in Task 3.
3. **A Direct To during the run-out:** the run-out is cleared with the rest of the stack (`clearTurnStack`), and the
   alert follows the Direct To's own rule. Pinned in Task 3.
4. **An edit of the leg after the target while a Direct To to an FPL 0 waypoint is active and its turn has started:**
   the same rule as for an FPL 0 leg applies. Pinned in Task 4.
5. **An edit that leaves the following leg instance alone,** such as a delete or insert further down the plan, or a
   user-waypoint edit elsewhere: no turn state changes (trainer run a7). Pinned in Task 4.
